# 六爻纳甲 · Claude Code Skill

> 让 Claude Code 按**六爻纳甲**体系断卦的一个 skill。
> 不是占卜软件，不含算法，不自动排盘——它做的只有一件事：**给模型喂料，给判断上尺。**

---

## 这是什么

一份约 3000 行的六爻知识库，打包成 Claude Code 的 skill。用户把排盘软件的输出（年月日时干支、旬空、六神、伏神、本卦变卦、动爻）贴进来，模型据此断事、推应期、复盘。

覆盖体系：**经占 · 火珠林 · 梅花易数 · 易林易隐**的象数与神煞。
只处理六爻。不碰八字、紫微、占星、风水、奇门、六壬。

---

## 为什么这样设计

市面上 AI 断卦的两种坏毛病：

**一是太玄。** 输出全是"气机流转""阴阳交感"，听着高级，落不了地。用户看完不知道下周该做什么。
**二是太机械。** 看见"父母旬空"就说"通知不来"，看见"官鬼持世"就说"有官职"。规则套得严丝合缝，卦象本身的画面全丢了。

第二种更危险，因为它看起来更"专业"，错得也更理直气壮。

火珠林体系把"数"（冲合刑害、旬空墓库、旺衰生克）发展到了极致。代价是：**它太会算，以至于让人以为算完就有答案。**

这个 skill 的处理办法，是把三层拆开：

| 层 | 目录 | 作用 | 定位 |
|---|---|---|---|
| **理** | `理/` | 定方向 | 原则。指导判断方向，不规定结论 |
| **象** | `象/` | 供意义 | 素材。供模型联想，不给答案 |
| **数** | `数/` | 做验证 | 尺子。用来量，不用来说话 |

工作顺序固定为：

```
观象 → 取象 → 验数 → 明理 → 答问
```

**明令禁止「数 → 结论」。** 数是尺子，不是答案。

---

## 一条自检标准

这份材料里每一句内容，都要过一道判断：

> **它是在"替模型思考"，还是在"给模型喂料"？**

- 替模型思考 → 删。例：「父母旬空就说通知不来」
- 给模型喂料 → 留并扩充。例：「父母可以是文书、合同、学历、房子、长辈、证件、辛苦」

判断力交给模型。大模型每更新一代，取象的火候和格局把握就上一个台阶——**这才是准确率提升的主要来源。** 规则固化得越死，越跟不上模型的进步。

所以这份 skill 会**随模型变强而逐步退让**。发现某条内容成了束缚，就该删掉它。

## 安装

```bash
git clone https://github.com/MsToyii/liuyao-najia.git
cp -r liuyao-najia ~/.claude/skills/liuyao
```

Windows：

```powershell
git clone https://github.com/MsToyii/liuyao-najia.git
Copy-Item -Recurse liuyao-najia "$env:USERPROFILE\.claude\skills\liuyao"
```

装完在 Claude Code 里输入 `/skills`，能看到 `liuyao` 就成功了。

## 使用

把排盘软件的完整输出贴进来，说清楚问什么：

```
新的一卦，卜问如下信息：

分类：事业    性别：男
背景：这个项目年内能不能签下来

起卦时间：2026-10-20 14:23
干支：丙午年 戊戌月 壬戌日 丁未时（旬空：子丑）
神煞：驿马-申 桃花-卯 贵人-巳午

　　　　玄武　兄弟戌土　▅▅▅▅▅
　　　　白虎　子孙申金　▅▅▅▅▅
　　　　螣蛇　父母午火　▅▅▅▅▅　世
　　　　勾陈　兄弟辰土　▅▅　▅▅
　　　　朱雀　官鬼寅木　▅▅　▅▅
　　　　青龙　妻财子水　▅▅　▅▅　应
```

模型会按「卦象定性 → 世爻 → 应爻 → 核心动爻 → 应期 → 结论建议」输出完整断语，不做引导式追问。

### 还能这样用

```
上次那个索赔的卦，钱到账了，少三成      → 调出原判断，对比复盘
我什么时候问过关于换供应商的卦           → 按关键词检索案例
复盘一下 10 月的卦                      → 列出待验证，逐条过
```

## 案例库

**不随本仓库分发。**

断卦的准确率只能靠复盘校准——判对只证明规则能用，断错才暴露规则缺在哪。所以 skill 支持把每卦存档，标「待验证」，等实际结果出来后逐条比对。

案例库默认放 `~/.claude/skills/liuyao/cases/`，按年月分目录，文件名 `case-NN-主题.md`。可用环境变量 `LIUYAO_CASES_DIR` 改到别处。

它是用户自己的资产：独立于 skill 代码，更新 skill 不会碰它，也**不建议推到公开仓库**——真实案例里的行业、组织、人际细节，脱敏再彻底也可能被认出来。

存档模板见 SKILL.md 第七节。

## 四条底线

1. **不编卦。** 卦里没有的信息不虚构。
2. **术语不硬伤。** 写"X冲Y""X合Y"之前查表。懂行的人一眼看出来。
3. **伦理边界。** 玄学不断生死。**不给宿命式结论**——求测人因为看了卦而放弃努力，是断卦者的责任。卦是示警，不是判决。
4. **诚实。** 错了当场认，说清错在哪一步；对了说清依据，不硬撑也不含糊。

## 常见误读（实战翻车里核出来的）

| 常见误读 | 正确读法 |
|---|---|
| 空 = 无 | 空是"名分未到"，是时机问题不是有无问题 |
| 冲 = 破 | 旺相之爻被冲是「动」，休囚之爻被冲才是「破」 |
| 伏 = 藏（出不来） | 伏神临日月 + 飞神受制 = 伏神**易出**，是吉象 |
| 卦名 = 吉凶 | 卦名是态势描述，不是终局判决。「未济」是尚未成，不是不成 |
